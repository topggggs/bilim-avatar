# Регистрация и вход

Обновление от 16 октября 2026. Вход и регистрация оформлены в общем стиле Bilim, без декоративных значков. Новая вкладка открывает форму входа; демонстрационный аккаунт доступен отдельной кнопкой.

## Режимы

- `AUTH_MODE=demo`: вымышленные сотрудники, регистрация по почте и телефону, тестовые ссылки и SMS-коды прямо в интерфейсе. Встроенный demo не обращается к реальным сервисам доставки. Этот режим не предназначен для реальных сотрудников.
- `AUTH_MODE=oidc`: исходный корпоративный вход Bilim. Локальная регистрация отключена; сотрудники должны быть заранее привязаны к проверенному OIDC subject.
- `AUTH_MODE=local`: самостоятельные аккаунты с подтверждённой почтой или телефоном. Требуются HTTPS, PostgreSQL, постоянный SESSION_SECRET и SMTP. Телефон включается при наличии трёх параметров Twilio. Демо-вход отключён.

Корпоративный SSO и пароли — отдельные режимы. Адрес почты или номер не связывают с существующим OIDC-пользователем автоматически. Для переноса сотрудников нужен отдельный процесс подтверждённого связывания; совпадение контактов само по себе недостаточно.

## Почта

1. Сотрудник указывает рабочую почту из `REGISTRATION_DOMAINS`.
2. Сервер отправляет одноразовую ссылку на 30 минут. До подтверждения пароль не запрашивается и учётная запись не создаётся.
3. По ссылке сотрудник указывает имя, необязательную должность, пароль с подтверждением и согласие.
4. Сервер проверяет ссылку повторно в транзакции, создаёт роль employee, записывает подтверждение и версию согласия. Руководитель и расширенные права назначаются администратором.

Для отправки: SMTP_HOST, SMTP_PORT (587 STARTTLS или 465 TLS), SMTP_FROM, SMTP_USER, SMTP_PASSWORD. Учётные данные SMTP необязательны только для доверенного relay; TLS обязателен. Библиотека не читает файлы и внешние URL, содержимое писем и токены не журналируются. Настройте SPF/DKIM/DMARC и проверяйте доставку на рабочих доменах отдельно.

## Телефон

Телефон нормализуется в E.164: `+7 (701) 123-45-67` → `+77011234567`. После SMS с шестью цифрами сотрудник заполняет те же поля и создаёт аккаунт. Вход — номер и пароль; восстановление — новый код SMS, затем новый пароль. Казахские номера поддерживаются с кодом +7.

Настройки отправки: TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_FROM. `SMS_ALLOWED_PREFIXES=+7` ограничивает направления; несколько префиксов разделяются запятыми. Доступность и стоимость доставки в стране, имя отправителя и географические разрешения нужно проверить в аккаунте поставщика. Ключи хранятся только на сервере. Если доставка недоступна, интерфейс сообщает об ошибке, а не имитирует успешную отправку.

Код действует 5 минут, доступно 5 проверок. Повторная отправка — через 60 секунд, не более пяти запросов на контакт за час. Новый код отменяет предыдущий для той же операции. Проверенный код выдаёт одноразовый случайный токен на 10 минут для завершения регистрации/сброса. Короткий SMS-код не используется как пароль или сессионный токен.

## Защита и хранение

- Пароль: 15–128 символов, разрешены пробелы, Unicode и вставка из менеджера паролей. Повторяющиеся распространённые фразы отклоняются базовым фильтром; полноценная база скомпрометированных паролей и MFA остаются следующими задачами.
- Хеширование: асинхронный scrypt, N=32768, r=8, p=3, случайная соль 16 байт, ключ 64 байта, timingSafeEqual.
- Ссылки: случайные 256 бит; в БД SHA-256, срок и отметка использования. SMS: HMAC-SHA-256 с серверным секретом, срок и число попыток.
- Аккаунты, токены и SMS-проверки отделены от users и профиля: local_accounts, auth_tokens, phone_challenges. PostgreSQL обеспечивает уникальность подтверждённых контактов; транзакция защищает от двойной регистрации. Старые файловые снимки обновляются без потери тестов и рангов.
- API не отдаёт пароли, хеши или коды администраторам/руководителям. Исключение — явно помеченный локальный демо-просмотр для автора запроса; NODE_ENV=production его отключает.
- HTTP-only cookie, SameSite=Lax, Secure вне demo; сессия на 8 часов. Сброс пароля и выход отзывают все локальные сессии аккаунта. Смена режима отвергает несовместимые cookie. Ответы API имеют Cache-Control: no-store.
- Вход ограничен по IP и аккаунту: после восьми неверных паролей блокировка на 15 минут. Запросы писем/SMS ограничены и по контакту; Origin проверяется для всех изменений. Лимитер IP локален процессу: для нескольких экземпляров нужен общий Redis limiter.
- Сброс не подтверждает существование аккаунта в публичном ответе. При неизвестном контакте также создаётся запрос, но завершить сброс невозможно.
- После успешной смены пароля вход выполняется заново. Проверенный контакт подставляется в форму входа; старый пароль больше не подходит.

## Первый администратор

После подтверждённой регистрации доверенный оператор сервера выполняет:

```bash
npm run db:role -- worker@company.kz admin
# Также принимаются ID пользователя или подтверждённый телефон.
```

Команда работает с настроенной БД, не доступна через публичный API и создаёт запись аудита. Администратор затем назначает руководителей в интерфейсе. Для demo FileStore запускайте CLI при остановленном API; в production используется PostgreSQL.

## Проверка

Автотесты проверяют полный путь почты и телефона, возврат из письма, неверные/просроченные/повторные токены, лимиты попыток, восстановление и отзыв сессий, роли, ошибки доставки, мобильную форму и доступность. SMTP и SMS проверены адаптерами с mock-доставкой; реальные письма и платные SMS не отправлялись. Корпоративный SSO проверен интерфейсом и ограничениями, без реального tenant Bilim. Тексты согласия, сроки хранения и договоры с поставщиками доставки требуют согласования перед запуском с реальными сотрудниками.
